판정: 수정 후 PASS

## 수정 내역 (원문 → 수정 | 이유)
- 캡션 "순서대로 하나씩 보면 돼요." → "순서대로 하나씩 확인해보세요. 환경에 따라 다른 원인이 있을 수 있어요." | 체크리스트 4가지만 보면 해결된다는 식으로 읽힐 수 있어 단정을 완화함

## 검수 결과 (이상 없음)
- PG사 이름·PG 고유 수치: 화면·캡션·해시태그에 없음. "PG", "#PG연동"은 일반 용어. 승인 호출 10분 제한 같은 수치는 화면에 나오지 않고 "PG 문서에서 확인"으로만 씀. 특정 PG 출처는 sources 필드에만 있음
- 도메인·HTTPS: 단정 없음. "운영 URL이 신청 정보와 맞는지 확인" 수준으로만 씀(research 불확실 항목, brand의 신청 시 운영 URL 입력과 맞음)
- 기술 내용: 키 세트 일치, 테스트 키 혼용 시 오류, 웹훅·리다이렉트 URL 점검, 서버 금액 대조, 중복 알림 멱등 처리, 심사·계약 끝난 결제수단만 라이브 사용 → 일반적으로 맞음. 추가 계약 시 키 세트 별도는 "나올 수 있어요"로 조건부 표현
- 이벤트 문구, "1~3일": 없음
- D+1: 표지 sub "D+1(영업일 기준)", point 장 "접수 후 D+1일 심사 (영업일 기준) / 보완 시 연장될 수 있어요", 캡션 2곳에 같은 단서 있음
- 개인·비사업자: point 장과 캡션 2곳에 "(심사·계약 후 이용)" 있음. 캡션에 업종·운영 방식에 따라 이용이 어려울 수 있다는 단서 있음
- 신청만으로 결제가 켜지지 않음: 캡션에 "심사 → 계약 → 연동 테스트" 순서와 함께 있음. point 장 제목에도 같은 순서
- "심사가 끝나면 이메일로 연동문서": brand의 "심사 완료 시 이메일로 연동문서 발송"과 일치. AI 명령문, 공식 연동문서, 제작 도구 외부 API·서버 기능 단서, 예시 프롬프트도 brand 원문과 맞음
- 세무 단서: 캡션에 "사업자등록·신고 의무는 판매 상황에 따라 별도로 확인" 있음
- 금지어(누구나/무조건/즉시/당일 승인): 없음
- 글자수(공백 포함, \n·* 제외): 제목 최대 19자(CTA), 본문 최대 79자(2번 주소 장), list 항목 최대 21자 → 모두 기준 이내
- 표지 sub와 캡션 첫 3줄에 핵심 강점 있음

## 사람 확인 필요 (법무/세무/사업팀에 물어볼 것)
- research 메모대로 PG 블로그 근거 일부는 검색 요약을 기준으로 했고 웹훅 문서는 구버전이다. 기술 문구는 일반론이라 게시에는 문제가 없지만, 시리즈로 이어갈 경우 개발팀이 공식 개발자 문서로 다시 확인해두면 좋다.
- 바이브페이 라이브 전환 시 운영 URL이 신청 정보와 다르면 결제에 실제로 영향이 있는지(심사 재확인 필요 여부)를 사업팀에 확인한다. 이번 편은 "확인해요" 수준이라 그대로 써도 된다.
