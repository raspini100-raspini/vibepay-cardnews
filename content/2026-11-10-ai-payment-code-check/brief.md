## 리스크 메모 (법·보안 단정 위험이 있는 부분)
1. **"AI 코드는 항상 위험" 단정 금지**: 2장면은 "짜일 수 있어요", "모를 수 있어요"로 가능성 표현. 근거(P5·P6)는 해외 가이드 글이며 통계가 아니다. "90% 맞고 10건당 1건 치명적" 등 수치는 사용 금지.
2. **공격 방법 구체화 금지**: "개발자도구로 금액을 바꿔 100원에 결제" 같은 재현 가능한 조작 방법·예시 금액을 화면·캡션에 쓰지 않는다. "금액이 바뀌어도 모를 수 있어요" 수준 유지.
3. **특정 PG 비노출**: 서버 대조·웹훅 근거는 특정 PG 공식 블로그·개발자 커뮤니티 출처지만 PG명·"10초/7회" 수치를 쓰지 않는다. 타사 비교·비방 금지.
4. **"이것만 하면 안전" 금지**: 3·4장면은 최소 점검 항목이지 보안 보증이 아니다. "완벽 보안", "해킹 걱정 끝" 금지. 바이브페이가 "금액 검증을 대신 해준다"거나 "코드를 대신 짜준다/보안을 보장한다"는 표현 금지(brand 사실은 AI 명령문 생성 + 공식 연동문서 전달까지).
5. **AI 연동 지원 단서**: "제작 도구가 외부 API 연결·서버 기능을 지원해야 함"을 캡션에 포함. 예시 프롬프트는 랜딩 원문 그대로 인용.
6. **바이브페이 강점 표현**: "즉시/당일 승인", "100% 통과", "심사 없이", "누구나", "무조건" 금지. "D+1일(영업일 기준), 보완 시 연장", "(심사·계약 후 이용)" 필수. 이번 편은 '사업자등록 없이'를 강조하지 않으므로 세무 단서 문구는 선택(넣어도 무방).
7. **이벤트**: 마감 일시·첫해 한정·VAT 별도·참여 방법은 6장면과 캡션 모두에 표기. 댓글-가입자 매칭 방식·가입 기한은 미정 [TODO] → "추후 안내", "댓글만 달면 자동 적용" 금지. 혜택은 관리비만 해당(가입비·수수료 제외) → "무료로 시작" 금지.
8. **렌더러 확인**: hook sub, list foot 필드 지원 여부와 stat big 문구("개인도 온라인 결제 받기") 줄바꿈 처리를 reel-producer가 확인. 미지원 필드는 내용 삭제 대신 캡션으로 이동.
